# 🏛️ EA Command Center

**An operating system for executive support: onboarding, preferences, and the EA's daily systems, all in one place.**

I built this to answer one question: *how does an Executive Assistant go from day one to fully running an executive's inbox, calendar, travel and admin in 90 days?* It gives the EA a structured onboarding path. It gives the executive one place to hand over everything the EA needs to know. And it sets daily and weekly rhythms that keep the work visible.

It was designed in Notion and is published here as Markdown, so anyone can copy it, fork it, or rebuild it in their own tool.

> 🧩 **Tip:** Duplicate the whole system for each new executive you support.

---

## How it works

```
 ┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
 │  1. ONBOARD          │──▶│  2. CAPTURE          │──▶│  3. RUN              │
 │  EA + client         │   │  Personal, business  │   │  Daily checklist,    │
 │  checklists,         │   │  info & preferences  │   │  EOD reports, task   │
 │  30-60-90 plan       │   │  (inbox, calendar…)  │   │  board, weekly 1:1s  │
 └──────────────────────┘   └──────────────────────┘   └──────────┬───────────┘
            ▲                                                      │
            └───────────── 4. IMPROVE: feedback, energy audit, ◀───┘
                              scorecard, 90-day review
```

## How success is measured

From the [EA Role Scorecard](06-ea-resources/ea-role-scorecard.md):

| Outcome | Measure | Target |
|---|---|---|
| Inbox under control | Unread or unprocessed at end of day | **0** |
| Calendar optimized | Scheduling conflicts | **0** |
| Hours returned to exec | Hours saved per week | **10+** |
| Responsiveness | Average response time to the exec | **< 1 hr** |
| Travel executed | Issues per trip | **0** |

## Security note

This system is built so that **sensitive data never sits in the workspace.** IDs, card numbers, account numbers, passwords and loyalty numbers stay in a shared password manager. These pages only record *where* things are stored and *who* has access.

---

## Using this template

1. Fork or download this repo, or rebuild the pages in Notion, Google Docs or any wiki.
2. Start with the **EA Onboarding Checklist** and work top to bottom during week one.
3. Run the **Client Onboarding Checklist** as the kickoff call, and fill in sections 2–4 from the answers.
4. Switch to the **daily and weekly** rhythms once the EA owns inbox and calendar.
